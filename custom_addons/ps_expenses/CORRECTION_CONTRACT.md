Current PO approval continues D6. This delegated first-release control is not tax/accounting policy, a bank reversal or financial GO. Finance remains NO_GO / REQUIRES_SPECIALIST_VERIFICATION.

The current owner opens one active correction case per trip with category (expense basis, funding record, authority/policy), reason and exact source revision. It snapshots monetary/status/reference facts and current policy/role bindings, not expense proof contents. Current separately assigned finance/cash officers own case processing; title/admin alone supplies no authority. All mutations lock trip→advance→expense→settlement→case; stale snapshots/revisions fail. Owner refresh after source/configuration changes records a new version, binds currently valid officers and invalidates earlier confirmations without rewriting original approvals or cash facts.

An active case holds new travel/funding/expense decisions, settlement approval/preparation/closure and new cancellation decisions. Already prepared uncertain external execution can still be reconciled; new source facts require case refresh. Historical closed workflow flags remain historical, but an active correction is visibly unresolved and monetary reports suppress a current-final interpretation. Original closure is not silently erased.

Finance can return an unexecuted/unclosed source for correction only after uncertainty is reconciled. Funding corrections cannot reset a disbursed advance. No settlement return after settlement cash has been recorded. A private linked-case authorization releases an unexecuted settlement's locks and returns preparation, preserving approval history. Current finance may route this even after a staff/policy change; owner then explicitly revises/resubmits affected sources and new officers review under current configuration. It does not deem old financial policy valid or automatically reassign immutable cash facts.

After actual execution/closure, or for a disputed/changed-policy basis that cannot safely be returned, finance records External Resolution Required with reason/reference. The hold remains. No direct change/delete/reopen of recorded money, no fabricated compensating payment or journal entry. An actual amount/reference/bank error requiring adjustment stays unresolved until a separately authorized financial correction process exists; this release does not pretend an external-reference note executes that process.

If investigation establishes that existing source facts and operative policy/role bindings remain valid and no source/amount adjustment is needed: current finance proposes a no-change disposition with reference/reason; distinct current cash officer confirms the exact snapshot; finance explicitly resolves. Any source or policy/assignment drift invalidates that chain. Resolution closes only this correction investigation, not the original travel/settlement/accounting workflow. Accounting stays NOT_VERIFIED. Operator declarations are not independent bank evidence.

Case audience is owner/current case finance/current case cash, not manager/other/public. Source-only monetary/status snapshot access does not grant expense proof access or permission to impersonate former officers. Audit is append-only; public field/default-context forgery, mixed forbidden batch, stale role/snapshot and duplicate/race attempts must fail.
